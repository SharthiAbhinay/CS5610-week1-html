Most Useful HTML tags

Throughout this lesson, I am learning which HTML tags I find the most useful. I will provide a list.

  • <nav> - wraps the navbar links
  • <ul> - the nav's link list and any other list content
  • <a> - creates a hyperlink
  • <h1> - the main heading of the page
  • <h2> - the subheading of the page
  • <section> - groups related content together
  • <div> - a generic container for content
  • <span> - a generic inline container for content
  • <p> - a paragraph of text
  • <footer> - the footer of the page

SEO Header tags

Part of this lesson is about researching SEO and how to use header tags. Here, I provide a list of the most important things I learned.

  • h1 serves as the headline. It is the main topic. It is for users and search engines. Since there is only one h1 per page, it should match search intent.
  • h2 header tags break the content into clear sections. they help users scan easily and help search engines such as google understand the sub topics.
  • h3 header tags organize details and dive deeper into specifics within the h2s.
  • search engines rewrite the title tags based off header tags.
  • golden rule: write headers that serve users/readers first, then SEO. Make them concise, easy to skim, and intentional. Do not keyword stuff. Clarity first.

Font Sizes

Here is an itemized list the same sentece with six different font sizes.

  • The bunny is round and fluffy.

    px, an absolute size: Use when you want the size to stay the same regardless of the user's device. For example when you want an icon to always stay the same size.

  • The bunny is round and fluffy.

    pt, an absolute size: Use when you want the the web page's printed font to be that exact size. Foe example for a stylesheet a user will print out. pt is taken from typography for printing.

  • The bunny is round and fluffy.

    cm, an absolute size: Use when you want the size to be in centimeters. It is a real-world measurement that is rarely used for screens. For example for a printed label that must match dimensions of a real-world object.

  • The bunny is round and fluffy.

    em, a relative size: Use when you want the size to be relative to the parent element. For example if you want the font to grow or shrink relative to the button's size.

  • The bunny is round and fluffy.

    rem, a relative size: Use when you want the size to be relative to the root element. For example this is good for general purpose and doesn't rely on a parent element, but the entire root of the html. Good for a user's font and browser settings..

  • The bunny is round and fluffy.

    vw, a relative size: Use when you want the size to be relative to the viewport width. For example this is good for long news headline, that will shrink on a narrow phone screen, but be long on a wide monitor. This is good without needing to separate rules for the view port.

Position Showcase

Two boxes per row. Smiley face box gets each positioning type applied. Sad face box is static. This lets you see how smiley face box's positioning affects the box next to it.

Static positioning is the default. The box is positioned according to the normal flow of the document. Use case is to use this for most elements on the page unless you want to break the normal flow of the document.

😁
😢

Relative positioning allows you to offset an element from its normal position. Use case is to move the element relative to the other element, in this case is putting the boxes side by side. Use without disturbing the other elements around it.

😁
😢

Absolute positioning allows you to position an element relative to its nearest positioned ancestor. Use case is to move the element to a specific location on the page, such as an icon that you dont want to move. Like putting it in the corner of a website.

😁
😢

Fixed positioning allows you to position an element relative to the viewport. Use case is for the element to always stay visible regardless of the user scrolling. This could be used for a 'back to top' button.

😁
😢

I will be using the fixed positioning for the footer, so it always stays at the bottom of the screen for the user to see.
